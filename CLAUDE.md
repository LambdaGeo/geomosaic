# CLAUDE.md

Guidance for Claude Code (and other contributors) working in this repository.

## What this project is

geomosaic assembles raster tiles into one validated virtual mosaic (a GDAL
`.vrt`). It is a small, general-purpose data-preparation library: it serves
any raster workflow, and is also the data-preparation step for spatial models
in the DisSModel ecosystem (`haloexec` reads the VRT block by block).

Keep it that way. geomosaic must **not** grow notions of execution engines,
blocks, halos, models or resampling. If a feature needs those, it belongs in
the consumer (e.g. haloexec) or upstream (e.g. gdalwarp), not here.

## Layout

```
src/geomosaic/core.py      all the logic: discover_tiles, inspect_tile,
                           build_mosaic_contract, write_vrt, TileInfo, MosaicContract
src/geomosaic/__init__.py  public API re-exports + __version__
tests/test_core.py         one test per validation check + VRT behaviour
tests/test_examples.py     runs every script in examples/
examples/tiled_export.py   synthetic end-to-end example (GEE-style export)
examples/mapbiomas_mangue.py multi-band MapBiomas time series (bundled sample + real export)
examples/data/             bundled sample tiles for examples
docs/                      mkdocs site; docs/api.md is generated from docstrings
```

## Commands

```bash
pip install -e ".[dev]"            # tests + lint
pip install -e ".[docs]"           # documentation
pytest                             # full suite (includes the examples)
ruff check src/ tests/ examples/   # lint (same command as CI)
mkdocs build --strict              # docs; warnings are errors
mkdocs serve                       # docs preview
python examples/tiled_export.py    # end-to-end demo
```

CI (`.github/workflows/ci.yml`) runs lint, tests on Python 3.10–3.12, a strict
docs build, and an sdist/wheel build + import check.
`docs_deploy.yml` publishes the site to GitHub Pages on push to `main`.

## Invariants — do not break these

- **Positions come from the geotransform, never from file names.**
  File names (e.g. GEE's `-<row>-<col>` suffix) must not influence placement.
- **`write_vrt` only accepts a `MosaicContract`.** A VRT must not be writable
  for an unvalidated tile set; do not add a shortcut that bypasses
  `build_mosaic_contract`.
- **Fail loudly, never silently.** Every condition that would make the VRT
  return wrong data (overlap, mixed dtype/nodata, misalignment, south-up,
  rotation, bad band) raises `ValueError` with a message naming the file(s)
  and the failed check. Overlaps are rejected by default (`allow_overlap=False`).
- **Runtime dependency is rasterio only.** The package does not import numpy
  or the GDAL Python bindings (`osgeo`); the VRT XML is written in pure Python.
  numpy is a dev-only dependency (tests, examples).
- **No pixel copying.** geomosaic writes a VRT; materializing a GeoTIFF is left
  to `gdal_translate` (documented in `docs/recipes.md`).

## Keep these in sync

The list of validation checks and their order is written in three places:

1. the `build_mosaic_contract` docstring (`core.py`),
2. `docs/validation.md` (table + one section per check, quoting the messages),
3. `README.md` ("Checks made by `build_mosaic_contract`").

When adding or changing a check or an error message, update all three and add
a test in `tests/test_core.py` proving the check fires. `docs/validation.md`
quotes messages verbatim — keep them identical to the code.

The docs API page is generated by mkdocstrings from the docstrings, so
docstrings must stay **numpy style** and render under `mkdocs build --strict`.

## Conventions

- English for code, docstrings, comments, messages, tests and docs.
- Lint policy shared with dissmodel/disscube/haloexec: ruff pinned to
  `>=0.16,<0.17` with no explicit `select` (see `[tool.ruff]` in
  `pyproject.toml`). If a pin bump changes results, fix the code or add a
  targeted `ignore` — do not re-pin silently.
- Tests use synthetic rasters written to `tmp_path`; never commit generated
  raster data (`*.tif`, `*.tiff`, `*.vrt` are git-ignored, except the bundled
  sample tiles in `examples/data/`). Examples must also be self-contained
  (no hardcoded local paths), since `tests/test_examples.py` runs them.
- Keep the public API small; anything new that is public goes in `__all__`.

## Downstream: haloexec

haloexec installs geomosaic straight from `main`
(`geomosaic @ git+https://github.com/LambdaGeo/geomosaic.git`) and tests the
integration in `tests/test_geomosaic_integration.py`, calling
`build_mosaic_contract(paths)` and `write_vrt(contract, path)`. Changing those
signatures or their defaults breaks haloexec's CI — keep them backward
compatible, or update haloexec in step.

## Working with the maintainer

Changes are usually delivered as patch files for `git am`, validated first by
applying them to a clean clone of `main` and running lint, the full test suite
and the strict docs build there.
